# Icons

<IconCount /> icons, exported as one `Icons` object from `src/components/icons.tsx`, mapping purpose names onto [Keyline](https://keylineicons.com) (`@keyline-icons/react`, stroke, rounded). Never import from `@keyline-icons/react` directly — the map is what keeps names semantic (`Icons.Delete`, not `BinIcon`) and gives every consumer one place to swap a glyph.

```tsx
import { Icons } from "@workspace/ui/components/icons"

<Icons.Add className="size-4" />
```

Each icon takes the Keyline SVG props (`size`, plus any SVG attribute). Size with `size-*`, colour with `text-*`. Decorative icons need `aria-hidden="true"`; an icon-only control needs an `aria-label` on the control, not on the icon.

## Adding an icon

1. Import the Keyline icon at the top of `icons.tsx`: `import { BinIcon } from "@keyline-icons/react"`.
2. Add one key to the `Icons` object, keeping it alphabetically sorted: `Delete: BinIcon`.
3. Name it after its **purpose**, not its shape — `Delete`, not `Bin`; `Expand`, not `ChevronDown`.
4. One key, one glyph — no two keys map to the same Keyline icon. If a second role needs an existing glyph, reuse that key.

A brand mark Keyline does not ship (`Icons.Claude`, `Icons.GitHub`, `Icons.Linear`, `Icons.Paper`, `Icons.Superset`) is declared as an inline `<svg>` component in `icons.tsx` itself, following Keyline's own conventions — `size` mapped onto `width`/`height`, `currentColor`, `aria-hidden` by default — so it sizes and colours identically to every other key. Each keeps the vendor's own geometry rather than Keyline's: its own `viewBox`, and `fill` where the vendor mark is filled instead of stroked.
